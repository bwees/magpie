## Conventions

- **Data blocks name their owner.** Each block below lists the context whose HTTP API and events feed it. Frontend work splits along these lines: one data block = one context's endpoints plus one Svelte component. Route names are indicative (`/api/<context>/…`); each context spec defines the final routes in OpenAPI.
- **Live data** comes from the app-wide WebSocket ([00](00-context-map.md#messaging-contract)). Each block lists the events it listens to. Components subscribe by event type and filter by ID; they never poll.
- **Actions** call the owning context's REST endpoint. The UI never chains calls across contexts to complete one action. Cross-context effects happen server-side through events.
- **States:** every data block has a skeleton while loading, an empty state with one plain sentence, and an inline error with Retry. Errors from one block never blank the page.
- **Optimistic UI** only for toggles (monitored, switches). Everything else waits for the response, then shows a toast.

## Visual style

- Dark mode only. `<html class="dark">`, no light theme, no theme toggle.
- Surfaces are neutral grayscale (shadcn-svelte neutral dark tokens). Teal (`oklch(0.76 0.12 195)`) is the only accent: primary buttons, active nav, badges, focus rings, progress, status checks. Red is used only for failures and destructive actions.
- Components: shadcn-svelte with Tailwind and lucide icons. Posters come from the Catalog image cache with the TMDB aspect ratio (2:3).
- Tokens live in `app.css`. The prototype's `src/routes/app.css` `.dark` block is the source of truth for values.

### Requester shell

Requesters ([ticket 15](../../.scratch/v1-spec/issues/15-users-and-auth.md)) see Home, Requests and title pages for titles they requested. They have no Movies/TV library, Activity or Settings. On phones the tabs are Home, Search and Requests. Search adds by creating a request. Everything Magpie-internal is hidden: indexers, queue internals, agents, release names, and settings.

## Search (top bar)

Finds titles in the library and adds new ones from TMDB. It is not interactive release search.

- **Desktop:** focusing the field opens a popover.
  - **Empty query:** "Trending this week" poster grid (5 columns).
  - **Typed query:** "In your library" (up to 4 rows: poster, name, year, pipeline stage), then "From TMDB" results.
  - **Result actions:** each TMDB card has **Add** (admin) or **Request** (requester), or a badge: In library / Requested.
  - **Closing:** Esc or a click outside.
- **Phone:** the search icon opens a full-screen overlay: input on top, close button, then the same sections in 3 columns.

| Block | Owner | Endpoint |
|---|---|---|
| Library hits | Catalog | `GET /api/catalog/titles?q=` |
| TMDB results / trending | Catalog (TMDB port) | `GET /api/catalog/discover?q=` (empty q = trending) |
| Status badge (In library / Requested) | Catalog + Requests | from both responses |
| Add (admin) / Request (requester) | Requests | `POST /api/requests`. An admin's request is approved at once → `requests.RequestApproved` → Catalog `TitleAdded{Origin: REQUEST}`. Catalog has no direct add endpoint. |

States: "Searching TMDB…" while waiting. If TMDB fails, library hits still show and the TMDB section reads "TMDB unavailable, retry".

## Home

Purpose: what needs me, what's moving, what's new.

Desktop layout: the library grid on the left, with a right column (380 px) holding **Needs you** above **Live now**. On phones the order is **Needs you**, then **Live now**, then **Recently active**.

| Block | Content | Owner | Endpoint · live events |
|---|---|---|---|
| Needs you | One row per attention item: dot (teal = action wanted, red icon = failure), title, one-line reason, one action button | Activity (attention list) | `GET /api/activity/attention` · `activity.AttentionChanged` |
| Live now | Card per active movie/episode (searching, downloading, importing, or a running transcode chip): poster, name, stage or chip, detail line, progress bar. Click → title page | Activity (pipeline projection) | `GET /api/activity/pipeline?active=true` · `acquisition.DownloadProgressed`, `transcode.JobProgressed`, `acquisition.SearchStarted/Completed`, stage events |
| Recently active | Poster grid. Stage badge (hidden when Available), progress bar overlay. Click → title page | Catalog (titles) + Activity (stage) | `GET /api/catalog/titles?sort=activity` + `GET /api/activity/pipeline?titles=` |

Attention item actions call the owner of the underlying item:

| Item | Button | Calls |
|---|---|---|
| Pending request | Approve | Requests `POST /api/requests/{id}/approve` |
| Title with no accepted release | Search again | Acquisition `POST /api/acquisition/searches` |
| Agent offline | View agent | Navigates to Activity → Agents (the item clears on `transcode.AgentOnline`) |
| Issue reported | Blocklist & re-grab | Requests `POST /api/requests/issues/{id}/actions {REGRAB}` |
| Transcode failed | Retry | Transcode `POST /api/transcode/jobs/{id}/retry` |
| Import failed / service unreachable | Open | Navigates to the title or Settings → Connections |

Empty: "All clear" in Needs you; "Nothing running" in Live now. Requester home: their requests with live stage, plus a trending row with Request buttons.

## Title page (movie and series)

### Hero

A full-width gradient taken from the poster colour.

**Hero content:**
- Poster, name, overview (3 lines on phones), chips: year, quality profile, "requested by X".
- Actions:
  - **Search**: automatic search.
  - **Interactive search**: opens the dialog below.
- Pipeline stage bar inside the hero: 5 segments (Requested, Searching, Downloading, Importing, Available). Available means Jellyfin confirmed the file, so the title is watchable. Done segments are filled, the current one is half-filled (red if failed), labels sit under each segment. A detail line below the bar shows the live detail and percent.
- **Chips beside the bar** for the work that happens after the file is watchable: **Subs** ("Subs …", "Subs ✓ en", "Subs ✓ en · es missing") and **Transcode** ("Transcode queued", "Transcode 41%", "Transcoded −62%", "Original kept", "Transcode failed"). They never move the main stage. For series the chips summarise the episodes; per-episode chips show in the Episodes tab.
- The prototype still shows the old 7-step bar (Subtitles and Transcoding as stages). The 5-stage bar plus chips replaces it.

**On phones:**
- Poster and name side by side, then the overview.
- Search and Interactive search as two equal buttons.
- Stage bar shows "<Stage> · step N of 5" above the segments, with no per-segment labels; chips wrap below.

| Block | Owner | Endpoint · events |
|---|---|---|
| Title metadata, poster | Catalog | `GET /api/catalog/titles/{id}` · `catalog.MonitoringChanged`, `EpisodeGroupChanged` |
| Stage, detail, Subs and Transcode chips | Activity (pipeline projection) | `GET /api/activity/pipeline?title={id}` · stage events, `subtitles.CoverageSettled`, `transcode.JobQueued/JobStarted`, `…Progressed` events |
| Search button | Acquisition | `POST /api/acquisition/searches {title}` |

### Tabs (left) and timeline (right)

Desktop: tabs on the left; the **Timeline** sits in a 340 px right column. Below `lg` the timeline becomes the first tab after Episodes.

| Tab | Content | Owner | Endpoint |
|---|---|---|---|
| Episodes (series) | One table per season. Header: "Season N", available/total, Monitored switch. Row: number, title, stage badge, Subs/Transcode chips (hidden on phones), detail (hidden on phones), icon-only search button (magnifying glass, tooltip "Search episode"). There is no episode × stage grid. | Catalog (episodes, monitoring) + Activity (stage, chips) + Acquisition (search) | `GET /api/catalog/titles/{id}` (seasons + episodes), `PATCH /api/catalog/titles/{id}/seasons/{n} {monitored}`, `POST /api/acquisition/searches {episodes}` |
| Files | Path, release name, size, video, audio tracks, subtitle tracks (with source and sync offset) | Library + Subtitles | `GET /api/library/files?title={id}`, `GET /api/subtitles/files/{mediaFileId}` |
| Settings | Quality profile (select, from `GET /api/acquisition/profiles`), Episode order (TMDB episode group, series only), Monitored, Exclude from transcoding, Subtitle language override, Delete title… | Catalog (profile, episode group, monitored, language override, delete) · Transcode (exclusion) | Each control calls its owner's endpoint |
| Timeline | Cards newest first: time, text, detail in mono (release names). Rejections and failures have a red border and tint. | Activity | `GET /api/activity/timeline?title={id}` · all durable events for the title |

Requester view: hero without Search buttons, the stage bar, the Timeline (no release names), and **Report issue** (type + text) → Requests `POST /api/requests/issues`.

## Interactive search dialog

Opened from **Interactive search**. Desktop: a dialog at 94 vw × 90 vh. Phone: full screen.

**Header:**
- Title, profile and cutoff chip (hidden on phones).
- Tracker pill: one small segment per tracker (pulsing teal = waiting, teal = done, red = failed, grey = skipped), plus "N / M trackers" or "All trackers answered", plus a red failure count.
- Accepted/rejected counts (hidden on phones), **Search again**, close.
- Hovering the pill (tap on touch) opens a list of tracker names, each with a spinner, teal check or red ✕. No timers, bars or counts.

**Body: quality buckets.**
- One section per quality the profile allows, in profile order, with a "Meets cutoff" badge on the cutoff quality. A final **Rejected** section follows.
- New releases append to the end of their bucket. Rows never reorder.
- The best release in each bucket gets a teal star and tinted border.
- Row: release name (mono; wraps on phones, truncated on desktop), format chips (CF names; LQ formats in red), Freeleech chip, rejection reason in red, score, size, seeders, indexer, and **Grab** (or **Override** for rejected rows).
- On phones the metadata and Grab move to a second line.
- Grab states: Grab → "Checking…" (blocked-file check) → Downloading. Or Rejected with a toast; Magpie then grabs the next best release automatically.

| Block | Owner | Endpoint · events |
|---|---|---|
| Start search | Acquisition | `POST /api/acquisition/searches {title, episodes, interactive: true}` → `SearchID` |
| Results, tracker status | Acquisition | `acquisition.SearchResultsReceived` (ephemeral, filtered by SearchID), `SearchCompleted`; `GET /api/acquisition/searches/{id}` for reconnect/refresh (in-memory cache, 30 min) |
| Grab / override | Acquisition | `POST /api/acquisition/searches/{id}/grab {release, override}` · `ReleaseGrabbed`, `ReleaseRejected` |

States: "Nothing yet…" in each empty bucket while running, "None found" once done. If every tracker fails: a banner "No trackers answered. Check Prowlarr", with a link to Settings → Indexers.

## Movies

- **Header:** "Movies", count, sort (Recently added / Title / Year), grid/table toggle (desktop only).
- **Filter chips with counts:** All, Missing, In progress, Available, Not transcoded. They scroll sideways on phones.
- **Grid:** the poster grid (about 3 per row on phones).
- **Table (desktop):** poster, title + year, profile, status badge, video summary, size.
- Phones: grid only.

| Block | Owner | Endpoint |
|---|---|---|
| Titles, profile | Catalog | `GET /api/catalog/titles?kind=movie&filter=&sort=` |
| Stage / status | Activity | `GET /api/activity/pipeline?titles=` |
| Video summary, size, "not transcoded" | Library | `GET /api/library/files?titles={id,…}&transcoded=false` |

Empty: "No movies yet. Search above to add one."

## TV

- **Header:** "TV", series count, total size.
- **Filter chips:** All, Missing episodes, Continuing, Ended.
- **One row per series:** poster, name, year, seasons, profile, status badge (Continuing/Ended), coverage ("14 / 19 episodes", "5 missing" in amber or "Complete" in green, with a bar), next airing, size. Click → title page.
- Phones: the coverage bar sits under the name; status, next airing and size are hidden.

| Block | Owner | Endpoint |
|---|---|---|
| Series, status, next airing | Catalog | `GET /api/catalog/titles?kind=series` |
| Coverage (have/total) | Library (`library.Reader.Coverage`) over Catalog (monitored episodes) | `GET /api/library/coverage?titles=` |
| Size | Library | same |

## Requests

Tabs: **Requests** (pending-count badge) and **Issues** (count).

- **Requests:**
  - Status chips with counts: Pending, Approved, Available, Declined, All.
  - Row: poster, title, scope (Movie / All seasons / Season N) + profile, requester avatar, name and time, status. Approved rows show the pipeline stage instead of a status badge.
  - Pending rows have **Approve** and **Decline**, which are full-width halves on phones.
- **Issues:** row with type badge (Video/Audio/Subtitle/Other), title + episode, text, reporter, time, comment count. Actions: **Re-run subtitles**, **Blocklist & re-grab**.
- Requesters see only their own requests and issues (unless the "view others' requests" toggle is on), with no approve or fix actions.

| Block | Owner | Endpoint · events |
|---|---|---|
| Requests | Requests | `GET /api/requests?status=` · `RequestApproved`, `RequestDeclined`, `RequestAvailable` |
| Approved row stage | Activity | `GET /api/activity/pipeline?titles=` |
| Approve / Decline | Requests | `POST /api/requests/{id}/approve`, `…/decline` |
| Issues, comments | Requests | `GET /api/requests/issues`, `POST /api/requests/issues/{id}/comments` |
| Issue actions | Requests | `POST /api/requests/issues/{id}/actions {REGRAB \| RERUN_SUBTITLES}` → `requests.IssueActionRequested` |

Empty: "Nothing here." / "No open issues."

## Settings (admin only)

- **Desktop:** left sub-nav with a "Search settings…" box that filters sections by name and keywords.
- **Phone:** the sub-nav becomes a dropdown; label/control rows stack.
- **Sections:** General, Connections, Library, Quality, Indexers, Downloads, Subtitles, Transcode, Agents, Users, Notifications.
- Each section writes only to its owning context (or platform, for Connections). The full catalogue with defaults and owners is in [12-settings.md](12-settings.md).

Special controls:
- **Connections** (platform-owned): card per service (TMDB, qBittorrent, Prowlarr, Jellyfin, OpenSubtitles) with a status badge and **Test**. Test shows a toast with the detected version and capabilities. Status updates live from `platform.ServiceHealthChanged`.
- **Library:** shows the hardlink check result inline (green: same filesystem; amber: copy fallback).
- **Indexers:** read-only list from Prowlarr (status, average response, priority input, seeding override select) and an "Open Prowlarr ↗" link.
- **Downloads:** blocked patterns as removable chips with an inline add field.
- **Subtitles:** wanted languages as a draggable ordered list with Forced / HI checkboxes (owner Catalog, `PUT /api/catalog/languages`); Whisper and sync settings and the OpenSubtitles quota badge (owner Subtitles).
- **Transcode:** target, preset, per-resolution caps (4 inputs), skip rules (low-bitrate % of cap, minimum saving), backlog count with **Re-scan library**.
- **Agents:** masked shared secret with copy (set by `MAGPIE_AGENT_SECRET`; no rotate button), a sample `docker run` command, the transfer cap.
- **Users:** table with role select and auto-approve switches.
- **Notifications:** per-user list of notification URLs (see below).

## Notifications

- **Bell:** opens a popover with the latest in-app notifications (newest first, unread dot, mark all read). Clicking one goes to its title or request. Owner: Activity, `GET /api/activity/notifications`, live `activity.NotificationCreated`.
- **Settings → Notifications** is per user and visible to every user, including requesters:
  - Each shoutrrr URL is a card with a label, the masked URL, **Send test**, and event checkboxes.
  - The event list is scoped by role: requesters see only their own request/issue events; admins also see approvals, issues, failures and pipeline successes.
  - An add-URL field shows example schemes (`discord://`, `telegram://`, `ntfy://`, `pushover://`, `smtp://`).
  - Owner: Activity, `GET/POST/PATCH/DELETE /api/activity/notification-urls`.

## Sign-in and first run

- **Sign-in:** Jellyfin username/password, or Quick Connect (shows a 6-digit code, polls until approved), plus a "Local admin" link. Owner: Identity.
- **First-run wizard** (no admin yet): local admin → TMDB key → qBittorrent → Prowlarr → Jellyfin → library paths (with the hardlink check) → default quality preset (`720p` / `1080p` / `2160p`) → wanted languages → OpenSubtitles login → transcode target → optional "Import from Sonarr/Radarr" ([11-migration.md](11-migration.md)). Connection steps write platform connection config; the rest call their owning context's endpoint. Each step can be skipped and revisited in Settings.
