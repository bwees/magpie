## Conventions

- **Data blocks name their owner.** Each block below lists the context whose HTTP API and events feed it. Frontend work splits along these lines: one data block = one context's endpoints plus one Svelte component. Route names are indicative (`/api/<context>/…`); each context spec defines the final routes in OpenAPI.
- **Live data** comes from the app-wide WebSocket ([00](00-context-map.md#messaging-contract)). Each block lists the events it listens to. Components subscribe by event type and filter by ID; they never poll.
- **Actions** call the owning context's REST endpoint. The UI never chains calls across contexts to complete one action. Cross-context effects happen server-side through events.
- **States:** every data block has a skeleton while loading, an empty state with one plain sentence, and an inline error with Retry. Errors from one block never blank the page.
- **Optimistic UI** only for toggles (monitored, switches). Everything else waits for the response, then shows a toast.

## Visual style

- Dark mode only. `<html class="dark">`, no light theme, no theme toggle.
- Surfaces are neutral grayscale (shadcn-svelte neutral dark tokens). Teal (`oklch(0.76 0.12 195)`) is the only accent: primary buttons, active nav, badges, focus rings, progress, status checks. Red is used only for failures and destructive actions.
- Components: shadcn-svelte with Tailwind and lucide icons. Posters come from the Catalog image cache with the TMDB aspect ratio (2:3).
- Tokens live in `app.css`. The prototype's `src/routes/app.css` `.dark` block is the source of truth for values.

### Requester shell

Requesters ([ticket 15](../../.scratch/v1-spec/issues/15-users-and-auth.md)) see Home, Requests and title pages for titles they requested. They have no Movies/TV library, Activity or Settings. On phones the tabs are Home, Search and Requests. Search adds by creating a request. Everything Magpie-internal is hidden: indexers, queue internals, agents, release names, and settings.

## Search (top bar)

Finds titles in the library and adds new ones from TMDB. It is not interactive release search.

- **Desktop:** focusing the field opens a popover.
  - **Empty query:** "Trending this week" poster grid (5 columns).
  - **Typed query:** "In your library" (up to 4 rows: poster, name, year, pipeline stage), then "From TMDB" results.
  - **Result actions:** each TMDB card has **Add** (admin) or **Request** (requester), or a badge: In library / Requested.
  - **Closing:** Esc or a click outside.
- **Phone:** the search icon opens a full-screen overlay: input on top, close button, then the same sections in 3 columns.

| Block | Owner | Endpoint |
|---|---|---|
| Library hits | Catalog | `GET /api/catalog/titles?q=` |
| TMDB results / trending | Catalog (TMDB port) | `GET /api/catalog/discover?q=` (empty q = trending) |
| Status badge (In library / Requested) | Catalog + Requests | from both responses |
| Add (admin) / Request (requester) | Requests | `POST /api/requests`. An admin's request is approved at once → `requests.RequestApproved` → Catalog `TitleAdded{Origin: REQUEST}`. Catalog has no direct add endpoint. |

States: "Searching TMDB…" while waiting. If TMDB fails, library hits still show and the TMDB section reads "TMDB unavailable, retry".

## Title page (movie and series)

### Hero

A full-width gradient taken from the poster colour.

**Hero content:**
- Poster, name, overview (3 lines on phones), chips: year, quality profile, "requested by X".
- Actions:
  - **Search**: automatic search.
  - **Interactive search** (movies only): opens the dialog below. A series is searched interactively by season or episode from the Episodes tab.
- Pipeline stage bar inside the hero: 5 segments (Requested, Searching, Downloading, Importing, Available). Available means the file is in the library and Jellyfin was asked to rescan it. Done segments are filled, the current one is half-filled (red if failed), labels sit under each segment. A detail line below the bar shows the live detail and percent.
- **Chips beside the bar** for the work that happens after the file is watchable: **Subs** ("Subs …", "Subs ✓ en", "Subs ✓ en · es missing") and **Transcode** ("Transcode queued", "Transcode 41%", "Transcode check 41%" while the agent checks its output, "Transcoded −62%", "Original kept", "Transcode failed"). They never move the main stage. For series the chips summarise the episodes; per-episode chips show in the Episodes tab.
- The prototype still shows the old 7-step bar (Subtitles and Transcoding as stages). The 5-stage bar plus chips replaces it.

**On phones:**
- Poster and name side by side, then the overview.
- Search and Interactive search as two equal buttons; a series has Search alone, full width.
- Stage bar shows "<Stage> · step N of 5" above the segments, with no per-segment labels; chips wrap below.

| Block | Owner | Endpoint · events |
|---|---|---|
| Title metadata, poster | Catalog | `GET /api/catalog/titles/{id}` · `catalog.MonitoringChanged`, `EpisodeGroupChanged` |
| Stage, detail, Subs and Transcode chips | Activity (pipeline projection) | `GET /api/activity/pipeline?title={id}` · `activity.ProjectionUpdated{PIPELINE, title}` (refetch), `acquisition.DownloadProgressed` and `transcode.JobProgressed` (live %) |
| Search button | Acquisition | `POST /api/acquisition/searches {title}` |

## Interactive search dialog

Opened by admins from **Interactive search** on a movie's title page, or from a season header or episode row in a series' Episodes tab. A season search lists that season's packs and episodes; an episode search lists the releases covering that episode, packs included. Releases for other episodes land in **Rejected** ("S02E02 wasn't searched for"). Desktop: a dialog at 94 vw × 90 vh. Phone: full screen. Closing it, or **Search again**, cancels a search that is still running.

**Header:**
- "Search · " and what is searched ("Dune: Part Two", "Severance Season 1", "Severance S01E02"), profile and cutoff chip (hidden on phones).
- Tracker pill: one small segment per tracker (pulsing teal = waiting, teal = done, red = failed, grey = skipped), plus "N / M trackers" or "All trackers answered", plus a red failure count.
- Accepted/rejected counts (hidden on phones), **Search again**, close.
- Hovering the pill (tap on touch) opens a list of tracker names, each with a spinner, teal check or red ✕ (a grey dash for skipped). No timers, bars or counts. A device without hover gets the tap popover.

**Body: quality buckets.**
- One section per quality item the profile allows (a group is one section), in profile order, with a "Meets cutoff" badge on the cutoff item and the items ranked above it. A final **Rejected** section follows.
- New releases append to the end of their bucket. Rows never reorder.
- The best release in each bucket (highest current rank) gets a teal star and tinted border.
- Row: release name (mono; wraps on phones, truncated on desktop), format chips (CF names; formats the profile scores below zero, such as LQ, in red), Freeleech chip, rejection reasons in red, score, size, seeders, indexer, and **Grab** (or **Override** for rejected rows).
- On phones the metadata and Grab move to a second line.
- Grab states: Grab → "Checking…" (blocked-file check) → Downloading. Or Rejected with a toast; Magpie then grabs the next best release automatically.

| Block | Owner | Endpoint · events |
|---|---|---|
| Start search | Acquisition | `POST /api/acquisition/searches {title, episodes, interactive: true}` → the search state with `searchId`; then subscribe to `search:<id>` and read `GET /searches/{id}` once for answers sent before the subscription |
| Results, tracker status | Acquisition | `acquisition.SearchResultsReceived` (ephemeral, filtered by SearchID), `SearchCompleted`; `GET /api/acquisition/searches/{id}` for reconnect/refresh (in-memory cache, 30 min) |
| Grab / override | Acquisition | `POST /api/acquisition/searches/{id}/grab {releaseId, override}` · `ReleaseGrabbed`, `ReleaseRejected` |
| Cancel | Acquisition | `DELETE /api/acquisition/searches/{id}` |

States: "Nothing yet…" in each empty bucket while running, "None found" once done. If every tracker fails: a banner "No trackers answered. Check Prowlarr", with a link to Settings → Indexers. If no indexer can search the title: "No indexer can search this title", with the same link. A search that couldn't start shows its error.

The client keeps the best-first order from the ranks: a new release's `rank` is its position among everything accepted so far, and earlier releases keep their order. A replayed or late event never moves a tracker back from `DONE`.

## Requests

Tabs: **Requests** (pending-count badge) and **Issues** (count).

- **Requests:**
  - Status chips with counts: Pending, Approved, Available, Declined, All.
  - Row: poster, title, scope (Movie / All seasons / Season N) + profile, requester avatar, name and time, status. Approved rows show the pipeline stage instead of a status badge.
  - Pending rows have **Approve** and **Decline**, which are full-width halves on phones.
- **Issues:** row with type badge (Video/Audio/Subtitle/Other), title + episode, text, reporter, time, comment count. Actions: **Re-run subtitles**, **Blocklist & re-grab** (full-width halves on phones); a pending fix shows "Re-grabbing" / "Re-running subtitles" instead.
  - Chips: **Open** (with count) and **Resolved**.
  - A row opens the thread in a side sheet (full width on phones): the report, the comments oldest first, a reply box, **Mark resolved** (reporter or admin) and the two fixes. `/requests?issue={id}`, the link in issue notifications, opens it.
  - **Blocklist & re-grab** answered `409 import-waiting` opens a warning naming the waiting release, with **View the release** (Activity → Imports, `/activity?tab=imports`) and **Remove it and continue** (Library's Remove & blocklist, then the REGRAB with `waitingRemoved`).
- Requesters see only their own requests and issues (unless the "view others' requests" toggle is on), with no approve or fix actions.

|---|---|---|

| Approved row stage | Activity | `GET /api/activity/pipeline?titles=` |
| Approve / Decline | Requests | `POST /api/requests/{id}/approve`, `…/decline` |

## Settings (admin only)

- **Desktop:** left sub-nav with a "Search settings…" box that filters sections by name and keywords.
- **Phone:** the sub-nav becomes a dropdown; label/control rows stack. Tablets (below `lg`) use the dropdown too, so the section gets the full width beside the rail.
- **Sections:** General, Connections, Library, Quality, Indexers, Downloads, Subtitles, Transcode, Agents, Users, Notifications.
- Each section writes only to its owning context (or platform, for Connections). The full catalogue with defaults and owners is in [12-settings.md](12-settings.md).

Special controls:
- **Connections** (platform-owned): card per service (TMDB, qBittorrent, Prowlarr, Jellyfin, OpenSubtitles) with a status badge and **Test**. Test shows a toast with the detected version and capabilities. Status updates live from `platform.ServiceHealthChanged`.
- **Library:** shows the hardlink check result inline (green: same filesystem; amber: copy fallback). **Scan library** starts a scan. A **Review matches** list (owner Catalog, `GET /api/catalog/scan-review`) shows folders the scan couldn't match with certainty: TMDB candidates, Match, Ignore, and an empty state ("Nothing to review"). Its pending count also feeds "Needs you".
- **Indexers:** read-only list from Prowlarr (status badge with the last error when failing, average response, priority and minimum-seeders inputs, seeding override select, seeding-goal inputs), **Sync now**, and an "Open Prowlarr ↗" link. The search timeout, result cache and sync interval sit below the table. Empty state when Prowlarr has no indexers; inline error when Prowlarr is unreachable. On phones the table scrolls sideways inside its card.
- **Downloads:** blocked patterns as removable chips with an inline add field.
- **Subtitles:** wanted languages as a draggable ordered list with Forced / HI checkboxes (owner Catalog, `PUT /api/catalog/languages`); Whisper and sync settings and the OpenSubtitles quota badge (owner Subtitles).
- **Transcode:** on/off, target, preset, per-resolution caps (4 inputs), skip rules (already target, low-bitrate % of cap, minimum saving, read-only Dolby Vision/HDR10+), collapsed per-encoder overrides, backlog counts with **Re-scan library**.
- **Agents:** masked shared secret with copy (set by `MAGPIE_AGENT_SECRET`; no rotate button), a sample `docker run` command, the transfer cap.
- **Users:** table with role select and auto-approve switches.
- **Notifications:** per-user list of notification URLs (see below).

## Notifications

- **Bell:** opens a popover with the latest in-app notifications (newest first, unread dot, mark all read). Clicking one goes to its title or request. Owner: Activity, `GET /api/activity/notifications`, live `activity.NotificationCreated`.
- **Settings → Notifications** is per user and visible to every user, including requesters:
  - Each shoutrrr URL is a card with a label, the masked URL, **Send test**, and event checkboxes.
  - The event list is scoped by role: requesters see only their own request/issue events; admins also see approvals, issues, failures and pipeline successes.
  - An add-URL field shows example schemes (`discord://`, `telegram://`, `ntfy://`, `pushover://`, `smtp://`).
  - Owner: Activity, `GET/POST/PATCH/DELETE /api/activity/notification-urls`.

## Sign-in and first run

- **Sign-in:** Jellyfin username/password, or Quick Connect (shows a 6-digit code, polls until approved), plus a "Local admin" link. Owner: Identity.
- **First-run wizard** (no admin yet): local admin → TMDB key → qBittorrent → Prowlarr → Jellyfin → library paths (with the hardlink check) → default quality preset (`720p` / `1080p` / `2160p`) → wanted languages → OpenSubtitles login → transcode target → optional "Import from Sonarr/Radarr" ([11-migration.md](11-migration.md)). Connection steps write platform connection config; the rest call their owning context's endpoint. Each step can be skipped and revisited in Settings.
